# 民事案件案由识别规则

## 参考表

使用 `assets/民事案件案由参考表_2025.xlsx`。该表包含二级案由说明、三级案由清单和第四级案由，不得依靠模型记忆另造案由名称。

`scripts/cause_catalog.py` 只用于检索候选项和校验名称。AI 必须结合材料中的诉争法律关系、请求权基础、主要诉求、主体关系及排除边界作出初步判断，不能把关键词得分直接当成结论。

## 识别时点

1. 清点文件并完成录音逐字稿检查；缺少逐字稿时仍按 `media.md` 暂停。
2. 对可读取材料做案件级初筛，只读取足以识别当事人、主要诉求、基础法律关系和争议对象的内容，不在此时完成逐件分类。
3. 先检索 3—5 个上位候选，锁定法律关系所在的一级或二级案由；再展开其全部三级、四级子案由，逐一核对适用要点和排除边界。
4. 提出一个“主要案由”和必要的“其他候选案由”，连同判断依据、排除理由和案由层级交给用户确认。
5. 用户确认主要案由、案件文件夹名称和目录方案后，才开始全量通读、分类、改名和归档。

## 层级规则

按下列顺序选择最具体且有材料支持的案由：

1. 第四级案由；
2. 没有适用的第四级案由时，选择第三级案由；
3. 没有适用的第三级案由时，选择第二级案由；
4. 确无更具体案由时，才选择第一级案由。

不能因为第四级名称更具体就忽略构成条件。材料不足以区分两个具体案由时，并列候选并标注“待确认”，不得擅自选择。

## 判断要素

- 当事人之间的基础法律关系；
- 原告实际主张和主要诉讼请求；
- 争议标的与违约、侵权或身份关系；
- 请求权竞合时当事人选择的请求权；
- 特殊侵权、劳动仲裁前置等专门边界；
- 参考表中的 `AI判别要点` 与 `易混淆与排除边界`。

多个法律关系均为诉争关系时，可以记录多个案由，但必须指定一个用于项目命名的 `primary_cause`。其他案由写入 `secondary_causes`，不得把多个案由拼成一个自造名称。

## 确认字段

在内部方案中保存：

```json
{
  "cause_of_action_review": {
    "status": "confirmed",
    "primary_cause": "追索劳动报酬纠纷",
    "level": 4,
    "hierarchy": ["劳动争议、人事争议、新就业形态用工纠纷", "劳动争议", "劳动合同纠纷", "追索劳动报酬纠纷"],
    "secondary_causes": ["工伤保险待遇纠纷"],
    "basis": "工资条、转账记录及加班沟通共同反映劳动报酬争议",
    "excluded_candidates": ["劳务合同纠纷：现有材料更接近劳动用工管理关系"],
    "confirmed_by_user": true
  }
}
```

`case_folder.cause_of_action` 必须等于已确认的 `primary_cause`。用户改变案由后，必须重新生成项目名称、成果文件名和成果标题。

## 统一标题

确认主要案由后统一生成：

- 项目文件夹：`{序号}-{原告简称}VS{被告简称}-{主要案由}`；
- Word 文件：`{主要案由}案件梳理报告.docx`；
- Word 标题：`{主要案由}案件梳理报告`；
- HTML 文件：`{主要案由}案件关键时间轴.html`；
- 页面标题：`{主要案由}｜案件关键时间轴`。

不得继续使用“法律案件梳理报告”“案件关键时间轴”等脱离案由的通用标题。

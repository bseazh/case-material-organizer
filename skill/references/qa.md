# 交付前 QA

逐项检查并在内部记录结果：

- 原始文件夹的文件数量、名称、哈希是否保持不变；
- 结果目录是否只有 `001` 至 `005` 五个一级分类目录；
- 原文件总数与已归档、重复、失败、未处理数量能否对平；
- 每个结果文件是否能反查原文件名和原路径；
- 所有改名是否符合命名规则，日期来源是否注明；
- 未提供逐字稿的音视频是否明确标记“未解析”，且未进入事实结论；
- Excel 第一张数据表是否为案件概览，而非单文件摘要；
- Excel 是否严格使用 6 张用户视图，且不包含内部编号、SHA-256、重复组、版本组、原文定位或机器路径；
- 是否先提取候选事实再合并事件，且没有错误合并同日不同事项；
- 事件发生时间、材料形成时间和文件修改时间是否分开；
- 时间轴是否按日期排序，每条是否显示可读的相关材料名称，并能通过内部 JSON 反查编号和路径；
- `index.txt` 是否包含案件链路摘要、数量统计、文件映射和异常项；
- `002 基础资料/index.md` 的数量与该目录实际文件数量是否一致；
- 空分类目录是否保留说明文件；
- 执行前 `归档目录预览.md` 是否完整展示改名后的五类目录树；
- 执行后 `归档结果目录.md` 是否以实际路径生成，且 AI 已在对话中直接展示目录树和 A/B/C 选项；
- Excel 是否可打开、无公式错误、筛选和冻结窗格可用；
- 若生成 HTML/PNG/PDF，文字是否清晰、节点顺序是否与 Excel 一致、附件引用是否存在。

关键项失败时先修复；无法修复时列出阻塞原因并请求用户确认，不得静默忽略。

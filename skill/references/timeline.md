# 时间轴与可视化规则

## 生成前提

时间轴只能根据已确认归档预览后的材料生成。存在录音时，必须先通过 `media.md` 的逐字稿检查。每条事件必须在内部数据中能追溯到一个或多个材料编号；律师版只显示可读的材料名称。

## 事件抽取

先按 `event-model.md` 将候选事实合并为事件。每个事件记录：事件编号、事件发生时间、材料形成时间、时间精度、地点/渠道、涉及主体、中性事件描述、主要材料编号、全部关联材料编号、原文定位、记载性质、冲突/待核。按事件发生时间升序；日期未知单列到末尾。

## 整体摘要

先写案件链路总览：起因、关键过程、争议集中点、当前结果或状态、相互印证材料、冲突和缺口。不要把每条证据摘要直接当成案件结论。

## 输出

Word 报告和可视化时间轴必须读取同一个已执行方案 JSON 中的最终事件。报告的关键时间轴表格和 HTML 均只包含 `timeline_role=main` 的案件主线；背景事项留在报告主体或总结部分。HTML 从相邻的已确认材料目录及其子目录递归查找附件，不依赖内部编号或机器路径。PNG/PDF 仅在用户明确要求时导出。

## 时间轴节点性质

使用 `材料记载`、`员工/当事人单方陈述`、`公司记录`、`客观系统记录`、`逐字稿材料记载`、`待核` 等标签。冲突不隐藏，在 `冲突/待核` 中具体说明。

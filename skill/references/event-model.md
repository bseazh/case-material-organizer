# 事件合并规则

## 核心原则

材料不是事件。一份材料可以记载多个事件；一个事件也可以由多份材料共同支持。先从材料中提取“候选事实”，再合并为事件，禁止按文件数量机械生成时间轴行。

## 三类时间必须分开

- `事件发生时间`：行为或事实实际发生的时间，用于时间轴排序；
- `材料形成时间`：合同签署、截图、表格导出、笔录制作等材料形成时间；
- `文件修改时间`：文件系统元数据，只用于文件清单和辅助核验，不得直接当作事件发生时间。

无法确认时填写“时间待核”，并记录时间来源与时间精度。不得用文件修改时间补造事件时间。

## 候选事实字段

每份材料先提取：候选事实编号、事件发生时间、材料形成时间、时间精度、地点/渠道、主体、行为、对象、金额/数量、结果、材料编号、原文定位、记载性质、冲突/待核。

一份材料包含多个独立行为时，拆成多个候选事实。例如同一聊天截图同时出现“调整班次”和“工资扣款”，应拆为两个候选事实。

## 可以合并为同一事件的条件

同时满足以下主要条件时才合并：

1. 时间相同或处于可解释的连续时间范围；
2. 核心主体相同；
3. 核心行为和对象相同；
4. 材料之间不存在无法并存的关键矛盾；
5. 合并不会丢失独立的法律或事实意义。

聊天截图、银行流水和工资表都指向同一次工资支付时，可合并为一个“工资支付/欠付事件”，并关联全部材料编号。

## 必须拆分的情况

- 同一天发生但行为不同，例如“签署合同”和“支付工资”；
- 主体不同，且不能证明属于同一行为；
- 同一通知包含多个独立生效事项；
- 同一事故之后的就医、报告、停工和赔付分别发生；
- 合并后无法准确描述各自时间、金额或结果；
- 用户要求按人员、合同或争议事项分别呈现。

同一天不是合并依据，只是候选线索。

## 冲突处理

日期、主体、金额、数量或结果冲突时，不挑选“看起来最合理”的版本，也不生成平均值。

- 仍可确认属于同一事件：保留一个事件，字段中并列不同记载及对应材料编号；
- 无法确认是否同一事件：暂时拆分，并标记“疑似同一事件，待确认”；
- 冲突影响事件顺序：使用最小可确认时间范围，时间精度标为“范围/待核”。

示例：`工资表记载实发 6,320 元（MAT-012），银行流水显示到账 5,640 元（MAT-019），差额及扣款依据待核。`

## 事件编号与材料关系

确认后的事件使用稳定编号 `EVT-001`、`EVT-002`。新增材料时不重排既有事件编号。每个事件保存：主要材料编号、全部关联材料编号、相互印证关系、冲突材料编号。

同一材料可关联多个事件，但必须注明对应页码、工作表、单元格区域、图片区域或文本段落等原文定位。

## 中性事件描述

使用“主体 + 行为 + 对象/结果”的可核验表达：

- 推荐：`工资表记载高雪8月工资扣减680元，高雪在聊天中提出异议。`
- 禁止：`公司恶意克扣高雪工资。`
- 推荐：`郭鹏提交离职申请，并要求结算工资、补贴和未休年假。`
- 禁止：`公司违法拒绝结算。`

除非材料本身是生效裁判或用户明确要求法律评价，否则不得把法律结论写成事件事实。

## 事件链路总览

总览不是文件摘要拼接，必须基于合并后的事件生成，并按以下顺序组织：

1. `起因`：关系如何形成、争议背景和最早关键事件；
2. `过程`：关键履行、沟通、变更和证据相互印证关系；
3. `争议`：各方对时间、主体、金额、责任的不同记载；
4. `现状`：最后可确认的状态、已发生处理和未完成事项；
5. `缺口`：缺少的原件、记录、主体说明、金额依据或其他待核材料。

总览中的每个关键判断必须能回溯到事件编号和材料编号。使用“材料显示”“某方主张”“系统记录”“尚待核实”等限定语。

## 合并结果 QA

- 是否存在“一份材料固定对应一行事件”的机械展开；
- 是否错误合并同日不同事项；
- 是否把文件修改时间当作事件时间；
- 是否为每个事件关联了材料编号和原文定位；
- 是否完整保留日期、主体和金额冲突；
- 是否使用中性语言；
- 案件总览是否覆盖“起因—过程—争议—现状—缺口”。

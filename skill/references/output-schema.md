# 输出结构与字段

## 结果目录

```text
{原文件夹名}_整理结果/
├── 001 主体信息/
├── 002 基础资料/
│   └── index.md
├── 003 委托材料/
├── 004 类案及法律检索/
├── 005 法律文书/
└── 整理结果/
    ├── 案件材料汇总.xlsx
    ├── 案件材料时间轴.html（可选）
    ├── 案件材料时间轴.png（可选）
    ├── 案件材料时间轴.pdf（可选）
    ├── 归档结果目录.md
    ├── index.txt
    └── 技术资料/
        └── 归档方案_已执行.json
```

原始文件夹不放入结果目录，不改变其内容。分类结果默认是副本。

## Excel 工作表顺序

1. `案件概览`：项目、核心内容。
2. `材料清单`：日期、材料名称、材料类型、主要内容、所在文件夹、处理状态。
3. `当事人信息`：姓名/公司、身份或角色、相关说明、待确认事项。
4. `音视频材料`：文件名称、对应逐字稿、处理情况、备注。
5. `案件时间轴`：日期、事件、相关人员/公司、相关材料、待确认事项。
6. `问题与待补材料`：问题、可能影响、建议补充、处理状态。

Excel 面向非技术用户，任何工作表都不得显示材料/事件/主体/问题的内部编号、SHA-256、重复组、版本组、原文定位或机器路径。这些数据仅保留在 `整理结果/技术资料/归档方案_已执行.json` 中。

## 链路总览要求

总览必须基于合并后的事件，说明“起因—过程—争议—现状—缺口”的整体链路，不得把单文件摘要拼接成结论。总览正文不显示内部编号；需要追溯时使用内部 JSON 和索引。

## index.txt

只保留两部分：第一部分为数据统计，仅显示文件总数、成功解析数和未解析数；第二部分为实际目录树。不得写案件冲突、内部编号、哈希、版本组或逐文件路径映射。

## 002/index.md

按材料日期升序；日期未知置于末尾。包含：日期、材料名称、相对路径、对应时间轴事项，不显示内部材料编号。

## 归档结果目录.md

必须根据已执行方案生成，只包含文件总数、成功解析数、未解析数、实际目录树和完成后的 A/B/C 选项。执行前预览仍展示原名与改名结果供用户确认；执行后的普通用户报告不显示逐文件映射。AI 交付时必须把目录树和选项直接展示在对话中。

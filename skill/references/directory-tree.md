# 目录树确认与交互

## 目的

分类和改名必须通过目录树让用户直观看到结果。Markdown 文件用于留档，但 AI 必须把目录树和下一步选项直接展示在对话中，不能只让用户打开文件查看。

## 执行前：拟归档目录树

完成内容提取、主体统一、重复识别、事件合并、分类和命名复核后，运行：

```bash
<PYTHON> scripts/build_tree.py <复核后的plan.json> --stage preview --out <工作目录>/归档目录预览.md
```

回复中必须直接展示：

1. 已确认的案件根文件夹名称，格式为 `序号-原告简称VS被告简称-案由`；
2. 用户选择的一级目录、二级目录及各自文件数量；
3. 改名后的文件名；
4. 空目录显示“本次未发现相关材料”；
5. 材料总数、已整理材料和需人工查看数量；
6. 下列 A/B/C 选项。

```text
A. 确认目录与命名，执行归档
B. 调整分类、命名或事件合并方案
C. 只保留预览，不复制文件
```

用户未选择 A 前，不得执行复制归档。目录树较长时可以按一级目录分段或使用 Markdown `<details>`，但不得省略文件名；用户明确选择“简略预览”时除外。

## 执行后：实际结果目录树

归档完成后，必须根据 `归档方案_已执行.json` 重新生成，不能沿用执行前预览：

```bash
<PYTHON> scripts/build_tree.py <结果目录>/整理结果/技术资料/归档方案_已执行.json --stage result --out <结果目录>/整理结果/技术资料/归档结果目录.md
```

回复中直接展示实际目录树、材料总数、已整理材料和需人工查看数量，并提供：

```text
A. 打开案件梳理报告
B. 打开独立可视化时间轴
C. 检查归档目录
```

## 展示规范

- 默认模式使用 `001` 至 `005`，自定义模式使用用户确认的材料目录；另设一个固定的 `整理结果` 成果目录，不属于材料分类；
- 默认模式必须展开显示 `002 基础资料` 的内容型二级目录，不能只显示 `002` 下的文件平铺结果；
- 根文件夹名称必须与 `case_folder_name` 一致；
- 执行前使用 `proposed_name`，执行后使用 `actual_target_relative_path`；
- 同名自动追加的编号必须以执行后目录树为准；
- 文件名按日期排序，`时间待核`置于每个目录末尾；
- 执行前可附“原文件名｜改名后文件名｜目录”表用于确认；执行后不再展示映射表；
- 对话中的目录树必须放在 fenced code block 中，防止缩进失真；
- 目录树只是确认界面，事实判断仍以 Word 报告、事件模型和原始材料为准。

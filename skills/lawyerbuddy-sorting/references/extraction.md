# 信息提取规则

## 通用原则

先保留原文，再形成结构化字段；无法确认的字段留空并标记“待核”，不得靠常识补齐。所有提取结果必须记录材料编号和原文定位。

开始提取前读取 `completeness.md`。不得从文件名、首页、活动工作表、关键词命中片段或既有摘要推定整份材料内容。材料较多或篇幅较长时分批读取，每批结果立即写入 `reading_coverage` 和 `fact_inventory`，防止上下文压缩导致遗漏。

## 按格式读取

- PDF：先提取文本层；文本为空、乱码或主要内容为图像时再 OCR。逐页记录页码。
- DOCX：读取正文、表格、页眉页脚、批注及可见文本；不得只读取正文段落。
- XLSX/XLSM：遍历所有可见工作表；记录工作表名和单元格范围。公式与显示值均需保留；不得只读第一张表。
- 图片：对聊天截图、票据、证件、照片中文字执行 OCR；保留图片尺寸和 OCR 置信情况。
- TXT/MD/JSON：按可检测编码读取；解析失败时尝试常见中文编码并记录实际编码。
- CSV/TSV：检测编码、分隔符和表头；保留原始行号，不把长账号自动转成科学计数法。
- 其他格式：登记但不猜测内容，标记“当前版本不支持解析”。

## OCR 触发条件

图片默认 OCR。PDF 在以下情况 OCR：无文本层、文本覆盖率极低、提取结果明显乱码、关键页是扫描图。已有清晰文本层时不重复 OCR；OCR 文本不能覆盖原文本。

OCR 不清晰时使用：`OCR部分可读`、`OCR低置信`、`OCR失败`。以 `[字迹不清]`、`[金额不清]` 标注局部，不自行补字；关键日期、金额、姓名不清时进入待核清单。

## 日期提取优先级

1. 正文明确记载的事件发生时间；
2. 签署、发送、支付、打卡等业务字段时间；
3. 材料形成时间；
4. 文件名中的候选日期；
5. 文件系统修改时间，仅作辅助核验。

事件发生时间、材料形成时间、文件修改时间分别保存。文件创建/修改时间不得替代事件发生时间。记录时间来源和精度：分钟、日期、月份、范围、待核。

## 结构化字段

- 金额：原文金额、币种、金额性质、付款方、收款方、支付状态；大小写金额冲突时并列保留。
- 主体：原文名称、标准名称候选、角色、上下文；按 `entity-resolution.md` 消歧。
- 地点/渠道：实体地点与线上渠道分开；无法确认具体地址时保留原文。
- 文号：完整保留机关/单位简称、年份、括号和序号，不擅自规范缺失字符。
- 账号：保留原文及账号类型；报告默认脱敏，仅显示末四位，原始材料不修改。
- 人员标识：姓名、工号、证件尾号、岗位分别提取；敏感字段只用于消歧和受控表格。

## 聊天截图

尽量识别平台/群名、发送人、接收人或群成员、消息时间、消息内容、引用消息、撤回/系统提示、图片/文件/语音附件及文件名。连续截图要识别重叠消息并去重；无法确认发送人或日期时不得把消息归属于特定主体。

一张截图包含多个独立事项时，拆为多个候选事实；聊天中的转述标记为“当事人/第三方陈述”，不直接写成客观事实。

## 最低提取记录

每个文件至少记录：材料编号、原路径、原文件名、格式、哈希、读取方式、读取状态、原文定位、候选日期、主体候选、内容摘要、异常与待核。

同时必须记录该文件的阅读覆盖明细：阅读单元类型、来源单元清单、应读单元数、已读单元数、已完成页码/工作表名/图片号/分段范围、覆盖依据和备注。来源单元清单必须由 `extract_content.py` 对原文件的页数、可见工作表或分段结果生成，不得根据已经读到的内容反推或手工缩小。应读单元数未知时不得标记完成。

每份材料完成后执行一次逐件核对：

1. 全部页、工作表、图片或分段是否均有读取记录；
2. 日期、主体、金额、行为、对象和结果是否分别检查；
3. 一份材料中的多个独立事实是否拆分；
4. 每项事实是否有精确来源定位；
5. 未发现实质事实时是否记录原因，而不是留下空摘要。

事实提取完成后再按 `completeness.md` 执行跨材料核对和法律事实复核。不得直接从单文件摘要生成案件总览。

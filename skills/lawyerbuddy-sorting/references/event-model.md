# 事件合并规则

## 核心原则

材料不是事件。一份材料可以记载多个事件；一个事件也可以由多份材料共同支持。先从材料中提取“候选事实”，再合并为事件，禁止按文件数量机械生成时间轴行。

## 三类时间必须分开

- `事件发生时间`：行为或事实实际发生的时间，用于时间轴排序；
- `材料形成时间`：合同签署、截图、表格导出、笔录制作等材料形成时间；
- `文件修改时间`：文件系统元数据，只用于文件清单和辅助核验，不得直接当作事件发生时间。

无法确认时填写“时间待核”，并记录时间来源与时间精度。不得用文件修改时间补造事件时间。

## 候选事实字段

每份材料先提取：候选事实编号、事件发生时间、材料形成时间、时间精度、地点/渠道、主体、行为、对象、金额/数量、结果、材料编号、原文定位、记载性质、冲突/待核。

一份材料包含多个独立行为时，拆成多个候选事实。例如同一聊天截图同时出现“调整班次”和“工资扣款”，应拆为两个候选事实。

## 每项事实的最终去向

完成事件合并后，不得只保留进入主时间轴的事实。`fact_inventory` 中的每项事实必须在 `fact_disposition` 中且只能有一个主要去向：

- `report_body`：进入案件总结或详细事实梳理；
- `timeline`：进入关键时间轴；
- `background`：进入主体或背景信息；
- `pending_confirmation`：进入冲突、缺口或待确认事项。

合并事件只是组织方式，不得删除组成该事件的独立事实细节。时间轴采用概括表述时，金额、数量、条件、异议、处理结果等细节仍须在报告正文中展开。每项事实的去向、来源材料和原文定位保存在内部数据中；律师可见报告不显示内部编号。

标记为具有法律相关性的事实必须进入 `legal_fact_map`。映射只说明该事实可能对应的法律要素及证据状态，不得把材料记载直接写成已经成立的法律结论。

## 逐字稿引导与全量反查

存在录音逐字稿时，先从逐字稿提取候选案件主线：关系形成、关键履行、付款或交付、争议爆发、协商过程、现状和材料缺口。该主线仅用于建立阅读顺序，不代表逐字稿具有更高证明力。

随后建立内部核对表，对每个候选事件逐项检查：

1. 哪些书面材料能够印证；
2. 哪些材料与逐字稿冲突；
3. 哪些重要事实只见于逐字稿；
4. 哪些重要书面事件未在逐字稿中出现；
5. 逐字稿提及但卷内缺失哪些材料。

只有完成上述反向核查，才能确定最终主线。不得因逐字稿叙述连贯而遗漏书面材料中的独立事件，也不得因缺少外部印证而删除对案件理解重要的逐字稿陈述；后者应明确标注“仅见逐字稿记载，待确认”。

## 可以合并为同一事件的条件

同时满足以下主要条件时才合并：

1. 时间相同或处于可解释的连续时间范围；
2. 核心主体相同；
3. 核心行为和对象相同；
4. 材料之间不存在无法并存的关键矛盾；
5. 合并不会丢失独立的法律或事实意义。

聊天截图、银行流水和工资表都指向同一次工资支付时，可合并为一个“工资支付/欠付事件”，并关联全部材料编号。

## 必须拆分的情况

- 同一天发生但行为不同，例如“签署合同”和“支付工资”；
- 主体不同，且不能证明属于同一行为；
- 同一通知包含多个独立生效事项；
- 同一事故之后的就医、报告、停工和赔付分别发生；
- 合并后无法准确描述各自时间、金额或结果；
- 用户要求按人员、合同或争议事项分别呈现。

同一天不是合并依据，只是候选线索。

## 冲突处理

日期、主体、金额、数量或结果冲突时，不挑选“看起来最合理”的版本，也不生成平均值。

- 仍可确认属于同一事件：保留一个事件，字段中并列不同记载及对应材料编号；
- 无法确认是否同一事件：暂时拆分，并标记“疑似同一事件，待确认”；
- 冲突影响事件顺序：使用最小可确认时间范围，时间精度标为“范围/待核”。

示例：`工资表记载实发 6,320 元（MAT-012），银行流水显示到账 5,640 元（MAT-019），差额及扣款依据待核。`

## 事件编号与材料关系

确认后的事件使用稳定编号 `EVT-001`、`EVT-002`。新增材料时不重排既有事件编号。每个事件保存：主要材料编号、全部关联材料编号、组成事件的 `fact_ids`、相互印证关系、冲突材料编号。主线事件缺少关联事实或材料时不得进入报告和时间轴。

同一材料可关联多个事件，但必须注明对应页码、工作表、单元格区域、图片区域或文本段落等原文定位。

## 中性事件描述

使用“主体 + 行为 + 对象/结果”的可核验表达：

- 推荐：`工资表记载高雪8月工资扣减680元，高雪在聊天中提出异议。`
- 禁止：`公司恶意克扣高雪工资。`
- 推荐：`郭鹏提交离职申请，并要求结算工资、补贴和未休年假。`
- 禁止：`公司违法拒绝结算。`

除非材料本身是生效裁判或用户明确要求法律评价，否则不得把法律结论写成事件事实。

## 案件主线与背景信息

每个合并事件增加 `timeline_role`：`main` 或 `background`。

- `main`：与争议形成、合同履行、付款、交付、沟通、检测、损害或当前处理状态直接相关，进入案件主时间轴；
- `background`：公司设立、历史工商变更、一般主体沿革等背景事项，写入 Word 报告的主体或背景说明，不进入主时间轴；
- 日期不明但对争议重要的事件仍属于 `main`，统一排在主时间轴末尾并标记“时间待确认”；
- 仅能说明材料存在、但没有形成独立事实节点的内容只进入 Word 报告的文件清单，不强行生成事件。

无法判断时标为 `main` 并写明“是否属于案件主线待确认”，不得因关键词机械删除重要事件。

主线事件可增加 `timeline_phase`，使用能够概括该组事实的中性阶段名称，例如“合同关系形成”“履行与付款”“争议发生与处置”。阶段必须由本案事件归纳，不得套用固定案件模板；无法可靠分阶段时留空，由可视化时间轴按年度分组。

## 事件链路总览

总览不是文件摘要拼接，必须基于合并后的事件生成，并按以下顺序组织：

1. `起因`：关系如何形成、争议背景和最早关键事件；
2. `过程`：关键履行、沟通、变更和证据相互印证关系；
3. `争议`：各方对时间、主体、金额、责任的不同记载；
4. `现状`：最后可确认的状态、已发生处理和未完成事项；
5. `缺口`：缺少的原件、记录、主体说明、金额依据或其他待核材料。

总览中的每个关键判断必须能回溯到事件编号和材料编号。使用“材料显示”“某方主张”“系统记录”“尚待核实”等限定语。

## 合并结果 QA

- 是否存在“一份材料固定对应一行事件”的机械展开；
- 是否错误合并同日不同事项；
- 是否把文件修改时间当作事件时间；
- 是否为每个事件关联了材料编号和原文定位；
- 是否完整保留日期、主体和金额冲突；
- 是否使用中性语言；
- 案件总览是否覆盖“起因—过程—争议—现状—缺口”。
- 存在逐字稿时，是否先形成候选主线再完成全部材料反向核查；
- 是否保留了逐字稿未提及但其他材料支持的重要事件；
- 仅由逐字稿支持的事件是否明确标注来源和待确认状态。

# 完整阅读与事实覆盖规则

## 目标

本规则按处理深度控制阅读范围。快速归档不承担案件事实分析；快速初稿完整核对关键材料，对其余材料做登记、机器检索和异常升级；专项核对只扩展用户指定问题；只有用户明确要求全量复核时，才要求全部材料、阅读单元和事实处置率均为 100%。不得把初稿表述为全量复核结论。

本规则所称“完整”仅适用于 `full-review`：全部材料均有读取结论；全部应读页、工作表、图片或文本分段均已处理；全部提取出的实质事实均已进入报告、时间轴、背景信息或待确认清单。快速初稿只声明“根据当前快速识别结果生成”。

## 四种内部模式

- `archive`：全部文件登记，依据目录、文件名、哈希和批量文本完成快速分类；不生成案件分析成果。
- `draft`：默认模式。全部文件登记，核对关键材料，快速生成初步 Word 报告和初步时间轴；普通材料允许延后核对。
- `focused-review`：用户指定金额、付款、主体、合同关系或具体材料后，只扩大相关核对范围并更新成果。
- `full-review`：用户明确要求时启用，执行本文件后续的全材料、全阅读单元三轮复核。

旧数据中的 `mainline`、`report`、`exhaustive` 分别兼容为 `draft`、`focused-review`、`full-review`，不得要求用户重做已有归档。

`analysis_scope` 必须记录关键材料、已核对材料、已机器提取材料、延后专项核对材料、无法读取材料、选择依据和说明。关键事实只能引用已经核对的材料。普通材料一旦出现主体、金额、日期、版本、责任口径冲突或新增关键事件，必须加入关键材料并核对。

## 分批处理

材料较多或单份材料较长时，必须分批读取并把中间结果写入结构化台账，不依赖当前对话上下文记忆。

- PDF：按页或连续页组读取，记录总页数、已读页码和遗漏页码。
- DOCX：正文、表格、页眉页脚、批注分别检查；长文按稳定段落范围分段，相邻分段保留必要重叠。
- XLSX/XLSM：逐张可见工作表读取，记录工作表名称；不得只读取活动工作表。
- 图片：每张图片为一个阅读单元；长截图可分区识别，但必须回到整图核对上下文。
- 聊天记录：按连续消息区间分段，识别重叠消息并去重；不得只抽取包含关键词的消息。
- 逐字稿：按时间段或段落分批读取，覆盖开头、中段和结尾；每段保留时间戳或段落范围。

每批完成后立即保存事实和来源定位。上下文不足时先停止新增分析、保存当前进度，再从未读单元继续；不得用已有摘要代替剩余内容。

## 三轮复核

### 第一轮：完整提取

逐份材料完成全文、全页、全工作表或全分段读取。每份材料必须形成：阅读范围、候选事实、主体、日期、金额、行为、结果、冲突、异常和待确认事项。没有实质事实的材料也要写明原因。

### 第二轮：跨材料核对

按主体、时间、金额、标的和行为反向检查全部事实：寻找相互印证、重复记载、不同版本、矛盾口径和材料缺口。逐字稿主线只是检索入口，必须检查书面材料中未被逐字稿提及的独立事实。

### 第三轮：法律事实复核

根据已确认案由，从合同或法律关系形成、权利义务、履行、违约或侵权行为、损害、因果关系、抗辩、时效、管辖和程序状态等维度复查。只标明事实与法律要素的关联及证据状态，不直接作事实认定或法律结论。

三轮复核必须分别记录完成状态、复核范围和发现的问题。不得用一个笼统的 `completed=true` 代替三轮记录。

## 数据要求

### reading_coverage

为每份材料记录：

- `material_id`
- `unit_type`：page、worksheet、image、segment、record 或 transcript_segment
- `units_expected`
- `units_completed`
- `source_units`：由原文件页数、可见工作表、图片清单或分段器形成的应读单元清单
- `completed_units`：逐项列出页码、工作表名、图片号或分段范围；条目数必须与 `units_completed` 一致
- `status`：complete、partial、unreadable 或 pending
- `coverage_basis`：原文件、OCR、匹配逐字稿或人工核对
- `notes`
- `no_relevant_fact_reason`：完整读取后未提取出实质事实时填写；有事实时留空

录音原件不由本 Skill 播放。已有完整逐字稿时，以逐字稿全部分段的覆盖情况作为录音内容覆盖依据；逐字稿缺失或不完整时仍按 `media.md` 暂停案件分析。

### fact_inventory

每项实质事实单独记录：事实编号、中性事实表述、记载性质、事件时间、主体、行为、对象、金额或数量、结果、来源材料、原文定位、冲突或待核事项、法律相关性。一个材料包含多个独立事实时必须拆分。

“记载性质”至少区分：客观记录、书面约定、当事人陈述、第三方陈述、系统记录和生效法律文书记载。不得把一方陈述直接标为客观事实。

### fact_disposition

每项事实必须且只能进入一个主要去向：

- `report_body`：进入案件总结或详细事实梳理；
- `timeline`：进入关键时间轴，同时也可在报告正文展开；
- `background`：作为主体或背景信息；
- `pending_confirmation`：进入待确认事项。

事实台账只登记与案件理解或法律分析有关的实质事实，因此不得以“内容太细”为由丢弃。确属无关内容不进入事实台账，但材料读取记录必须说明未发现相关实质事实。

### legal_fact_map

按本案案由建立“法律要素—已有事实—来源材料—证据状态—待确认事项”映射。所有标记为具有法律相关性的事实都必须至少关联一个法律要素；同一事实可以关联多个要素。

## 全量复核覆盖率

覆盖率由程序根据明细重新计算，不能只相信预先填写的百分比：

```text
材料覆盖率 = 状态为 complete 的材料数 / 全部材料数
阅读单元覆盖率 = 已读页、工作表、图片或分段数 / 应读总数
事实处置率 = 已进入报告、时间轴、背景或待确认清单的事实数 / 全部提取事实数
```

三项均须达到 100%。`units_expected` 未知、为零或缺失时，阅读单元覆盖率不得视为完成；应先从原文件或提取工具形成 `source_units`。`units_expected` 必须等于来源清单数量，`completed_units` 必须逐项覆盖来源清单，不能用自行填写的较小数字规避末页、其他工作表或最后分段。重复件和不同版本仍分别记录阅读结论，不能因文件相似而跳过未核验内容。

## 成果停止条件

`draft` 出现以下任一情况不得生成初稿：全部材料尚未登记；关键材料未完成核对；案件主体为空；案件概况为空；主要争议为空；没有至少一个有来源的主线事件；报告中的事实没有来源或引用未核对材料；录音缺少逐字稿或对应关系未确认。起因、过程、现状、缺口等细分内容不足时，列入“待确认事项”，不触发全材料重扫。

`focused-review` 在 `draft` 基础上要求记录用户指定问题、完成相关材料核对，并更新相应事实、报告和时间轴；不要求无关材料达到 100%。

`full-review` 模式另外适用以下停止条件：

- 任一材料尚未读取、只读部分内容或无法确认读取范围；
- 任一阅读单元遗漏；
- 任一实质事实没有最终去向；
- 任一具有法律相关性的事实没有进入法律要素映射；
- 三轮复核任一轮未完成；
- 录音缺少完整逐字稿或对应关系未确认。

普通文档或图片存在局部读取失败时，分类、复制和规范命名可以继续；初稿把相关内容列为“需人工查看”或“待确认”，不得把未读内容写成确定事实。录音缺少完整逐字稿或对应关系未确认属于 `media.md` 规定的案件级暂停条件。补齐后只需继续未完成单元。

## 完成声明

只有全部门禁通过后，才可以写“已完整阅读并梳理现有材料”。否则只能写“已根据当前可读取材料形成阶段性整理”，并列出未完成范围。不得用“文件数量已经对平”替代内容完整性声明。
